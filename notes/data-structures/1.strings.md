# Strings

## 1. Description and declaration

A string is an immutable sequence of characters used to represent text. Immutable means that once a string is created, its characters cannot be changed in place. Operations such as replacing, removing, or appending characters return a new string.

### Python

```python
text = "Data structures"
character = text[0]

print(text)       # Data structures
print(character)  # D
```

### TypeScript

```typescript
const text: string = "Data structures";
const character: string = text[0];

console.log(text);      // Data structures
console.log(character); // D
```

### Key properties

- Strings preserve character order.
- Indexes are zero-based.
- Duplicate characters are allowed.
- Character access is constant time in the common indexing model.
- Strings are immutable in both Python and TypeScript.
- Python indexes Unicode code points, while JavaScript and TypeScript index UTF-16 code units. This distinction matters for some emoji and uncommon Unicode characters.

```python
# Python: modification creates a new string
text = "cat"
updated = "b" + text[1:]

print(text)     # cat
print(updated)  # bat
```

```typescript
// TypeScript: modification creates a new string
const text: string = "cat";
const updated: string = "b" + text.slice(1);

console.log(text);    // cat
console.log(updated); // bat
```

## 2. Complexity model

A string does not have one general time complexity. The cost depends on the operation, the number of characters inspected, and whether a new string must be created.

Throughout this document:

- $n$ is the length of the input string.
- $m$ is the length of another string or search pattern.
- $k$ is the number of characters in the resulting substring.

### General rules

1. Reading stored metadata, such as the length, is usually $O(1)$.
2. Accessing a character by index is $O(1)$ under the language's native indexing model.
3. Inspecting every character is $O(n)$.
4. Creating a new string of length $k$ requires $O(k)$ time and space.
5. Comparing two strings may inspect up to the length of the shorter string.
6. Basic substring search can require $O(n \cdot m)$ in the worst case; specialized algorithms can improve this to $O(n + m)$.

### Complexity summary

| Operation | Time complexity | Extra space | Reason |
| --- | ---: | ---: | --- |
| Length | $O(1)$ | $O(1)$ | The length is stored by the runtime. |
| Character access | $O(1)$ | $O(1)$ | Direct indexed access. |
| Full traversal | $O(n)$ | $O(1)$ | Every character is inspected once. |
| Slice or substring | $O(k)$ | $O(k)$ | A new string of length $k$ is created. |
| Concatenation | $O(n + m)$ | $O(n + m)$ | Both operands are copied into a new string. |
| Remove or replace | $O(n)$ typical | $O(n)$ | A new string is built. |
| Trim or case conversion | $O(n)$ | $O(n)$ | Characters must be inspected and copied. |
| Reverse | $O(n)$ | $O(n)$ | All characters are copied in reverse order. |
| Equality or ordering | $O(\min(n,m))$ | $O(1)$ | Comparison stops at the first difference. |
| Basic substring search | $O(n \cdot m)$ worst case | $O(1)$ | The pattern may be checked at many positions. |
| Reference/value copy | $O(1)$ | $O(1)$ | Assignment does not copy every character. |

These are practical asymptotic bounds for algorithm analysis. Exact behavior can vary by runtime, search implementation, and Unicode representation.

## 3. Where this fits in my mental model

### When I reach for strings

I reach for a string when the input is naturally an ordered sequence of characters and I need one or more of these operations:

- Comparing prefixes, suffixes, or complete sequences.
- Finding a character, word, or pattern.
- Counting character frequencies.
- Detecting palindromes or anagrams.
- Parsing commands, paths, dates, or formatted input.
- Processing substrings with two pointers or a sliding window.
- Building keys for a hash map or set.

### Common problem patterns

| Problem type | Recommended technique | Typical complexity |
| --- | --- | ---: |
| Palindrome validation | Two pointers | $O(n)$ |
| Anagram detection | Frequency array or hash map | $O(n + m)$ |
| Longest substring without repetition | Sliding window and hash map | $O(n)$ |
| Fixed-size substring conditions | Sliding window | $O(n)$ |
| Simple prefix or suffix check | Direct comparison | $O(m)$ |
| Exact pattern search | KMP or Z algorithm | $O(n + m)$ |
| Repeated substring equality | Rolling hash | $O(n)$ preprocessing, $O(1)$ query |
| Many prefix searches | Trie | $O(m)$ per query |
| Character counting | Frequency array or hash map | $O(n)$ |
| Lexicographical ordering | Sort or direct comparison | Usually $O(n \log n)$ for sorting |

### Example: frequency map

```python
# Python
text = "banana"
frequency = {}

for character in text:
    frequency[character] = frequency.get(character, 0) + 1

print(frequency)  # {'b': 1, 'a': 3, 'n': 2}
```

```typescript
// TypeScript
const text: string = "banana";
const frequency = new Map<string, number>();

for (const character of text) {
    frequency.set(character, (frequency.get(character) ?? 0) + 1);
}

console.log(Object.fromEntries(frequency)); // { b: 1, a: 3, n: 2 }
```

### When I choose something else

Convert the string to a list or array of characters when the algorithm requires frequent modifications, sorting, swapping, or removal in the middle. Rebuilding an immutable string after every change can make an otherwise linear algorithm quadratic.

## 4. Operations cheatsheet

Assume $n$ is the string length, $m$ is the length of another string or pattern, and $k$ is the number of characters in the result.

| Operation | Python | TypeScript | Time | Extra space |
| --- | --- | --- | ---: | ---: |
| Declare | `text = "hello"` | `const text: string = "hello"` | $O(n)$ | $O(n)$ |
| Length | `len(text)` | `text.length` | $O(1)$ | $O(1)$ |
| Character access | `text[index]` | `text[index]` | $O(1)$ | $O(1)$ |
| Contains pattern | `pattern in text` | `text.includes(pattern)` | $O(n \cdot m)$ worst case | $O(1)$ |
| Find first index | `text.find(pattern)` | `text.indexOf(pattern)` | $O(n \cdot m)$ worst case | $O(1)$ |
| Starts with | `text.startswith(pattern)` | `text.startsWith(pattern)` | $O(m)$ | $O(1)$ |
| Ends with | `text.endswith(pattern)` | `text.endsWith(pattern)` | $O(m)$ | $O(1)$ |
| Append / concatenate | `text + other` | `text + other` | $O(n + m)$ | $O(n + m)$ |
| Copy reference/value | `copy = text` | `const copy = text` | $O(1)$ | $O(1)$ |
| Slice | `text[start:end]` | `text.slice(start, end)` | $O(k)$ | $O(k)$ |
| Substring from index | `text[start:]` | `text.substring(start)` | $O(k)$ | $O(k)$ |
| Remove one character | `text[:i] + text[i + 1:]` | `text.slice(0, i) + text.slice(i + 1)` | $O(n)$ | $O(n)$ |
| Trim both ends | `text.strip()` | `text.trim()` | $O(n)$ | $O(n)$ |
| Trim start | `text.lstrip()` | `text.trimStart()` | $O(n)$ | $O(n)$ |
| Trim end | `text.rstrip()` | `text.trimEnd()` | $O(n)$ | $O(n)$ |
| Lowercase | `text.lower()` | `text.toLowerCase()` | $O(n)$ | $O(n)$ |
| Uppercase | `text.upper()` | `text.toUpperCase()` | $O(n)$ | $O(n)$ |
| Reverse | `text[::-1]` | `Array.from(text).reverse().join("")` | $O(n)$ | $O(n)$ |
| Replace | `text.replace(old, new)` | `text.replace(old, new)` | $O(n)$ typical | $O(n)$ |
| Replace all | `text.replace(old, new)` | `text.replaceAll(old, new)` | $O(n)$ typical | $O(n)$ |
| Split | `text.split(separator)` | `text.split(separator)` | $O(n)$ | $O(n)$ |
| Join parts | `separator.join(parts)` | `parts.join(separator)` | $O(n)$ | $O(n)$ |
| Equality | `first == second` | `first === second` | $O(\min(n,m))$ | $O(1)$ |
| Count non-empty pattern | `text.count(pattern)` | `text.split(pattern).length - 1` | $O(n \cdot m)$ worst case | Python: $O(1)$; TS: $O(n)$ |
| Sort characters | `"".join(sorted(text))` | `Array.from(text).sort().join("")` | $O(n \log n)$ | $O(n)$ |

### Quick examples

```python
# Python
text = "  Data Structures  "
normalized = text.strip().lower()
words = normalized.split()
reversed_text = normalized[::-1]

print(normalized)     # data structures
print(words)          # ['data', 'structures']
print(reversed_text)  # serutcurts atad
```

```typescript
// TypeScript
const text: string = "  Data Structures  ";
const normalized: string = text.trim().toLowerCase();
const words: string[] = normalized.split(/\s+/);
const reversedText: string = Array.from(normalized).reverse().join("");

console.log(normalized);   // data structures
console.log(words);        // ['data', 'structures']
console.log(reversedText); // serutcurts atad
```

**Replacement difference:** Python's `str.replace` replaces every match by default. TypeScript's `String.replace` replaces only the first string match, so I use `replaceAll` when I mean every match.

## 5. Important considerations

### Strings are immutable

Operations that appear to modify a string allocate a new value. If an algorithm performs many updates, convert the string to a mutable collection, modify it, and join it once.

```python
# Python
characters = list("cat")
characters[0] = "b"
result = "".join(characters)  # bat
```

```typescript
// TypeScript
const characters: string[] = Array.from("cat");
characters[0] = "b";
const result: string = characters.join(""); // bat
```

### Repeated concatenation

Repeatedly growing a string inside a loop may lead to quadratic work because every intermediate value can be copied. Store the pieces and join them once when performance matters.

### Search complexity depends on the algorithm

Built-in search methods are convenient, but their exact implementation is runtime-dependent. I keep the conservative $O(n \cdot m)$ worst-case bound in mind unless the constraints specify otherwise or I implement an algorithm such as KMP, which runs in $O(n + m)$.

### Unicode requires care

Python and TypeScript do not index strings in exactly the same way. `Array.from(text)` handles Unicode code points better than `text.split("")`, but user-perceived characters composed of multiple code points may still require grapheme-aware processing.

### Why I prefer `slice` in TypeScript

`slice(start, end)` supports negative indexes and behaves predictably when `start > end`. `substring(start, end)` converts negative indexes to zero and swaps its arguments when necessary. I prefer `slice` because its behavior is easier for me to reason about consistently.

### Empty-pattern counting differs

The split-based TypeScript counting expression assumes a non-empty pattern. Python's `"abc".count("")` returns `4`, while JavaScript's `"abc".split("").length - 1` returns `3`.

### Check the judge's ECMAScript version

`trimStart` and `trimEnd` require ES2019, and `replaceAll` requires ES2021. Older runtimes may require regular-expression alternatives.
