# Stacks and Queues

## 1. Description and declaration

A stack processes elements in **last in, first out** (LIFO) order. A queue processes elements in **first in, first out** (FIFO) order.

Python lists and TypeScript arrays work well as stacks. For queues, Python provides `collections.deque`. In TypeScript competitive programming, an array with a head index avoids the $O(n)$ cost of repeatedly calling `shift()`.

### Python

```python
from collections import deque

stack = []
stack.append("first")
stack.append("last")
print(stack.pop())  # last

queue = deque(["first"])
queue.append("last")
print(queue.popleft())  # first
```

### TypeScript

```typescript
const stack: string[] = [];
stack.push("first");
stack.push("last");
console.log(stack.pop()); // last

const queue: string[] = ["first", "last"];
let head = 0;
console.log(queue[head]); // first
head += 1;
```

### Key properties

- A stack adds and removes elements from the same end.
- A queue adds at the back and removes from the front.
- Stack `push` and `pop` are $O(1)$ amortized.
- Deque append and removal from either end are $O(1)$.
- TypeScript `shift()` is $O(n)$ because remaining elements move.
- Both structures restrict access order to simplify algorithms.

## 2. Complexity model

Throughout this document, $n$ is the number of stored elements.

### Complexity summary

| Operation | Stack | Queue/deque | Extra space |
| --- | ---: | ---: | ---: |
| Read next element | $O(1)$ | $O(1)$ | $O(1)$ |
| Add element | $O(1)$ amortized | $O(1)$ amortized | $O(1)$ amortized |
| Remove element | $O(1)$ | $O(1)$ | $O(1)$ |
| Search | $O(n)$ | $O(n)$ | $O(1)$ |
| Length | $O(1)$ | $O(1)$ | $O(1)$ |
| Copy | $O(n)$ | $O(n)$ | $O(n)$ |

A TypeScript queue implemented with `shift()` has $O(n)$ removal. Using a head index keeps dequeue operations at $O(1)$, although the consumed prefix remains allocated until the array is compacted or discarded.

## 3. Competitive programming use cases

### When to use a stack

- Matching brackets and validating nested structures.
- Depth-first search implemented iteratively.
- Evaluating expressions.
- Undo operations and path simplification.
- Next greater or smaller element with a monotonic stack.
- Simulating recursive call order.

### When to use a queue

- Breadth-first search and shortest paths in unweighted graphs.
- Level-order tree traversal.
- Processing tasks in arrival order.
- Multi-source BFS.
- Maintaining candidates in a sliding-window deque.

### Common problem patterns

| Problem type | Structure | Typical complexity |
| --- | --- | ---: |
| Valid parentheses | Stack | $O(n)$ |
| Next greater element | Monotonic stack | $O(n)$ |
| Evaluate postfix expression | Stack | $O(n)$ |
| Unweighted shortest path | Queue with BFS | $O(V + E)$ |
| Tree level order | Queue | $O(n)$ |
| Sliding-window maximum | Monotonic deque | $O(n)$ |

### Example: valid parentheses with a stack

Push opening brackets. For each closing bracket, the top of the stack must contain its matching opening bracket.

```python
# Python
text = "{[()]}"
matching = {")": "(", "]": "[", "}": "{"}
stack = []
valid = True

for bracket in text:
    if bracket in "([{":
        stack.append(bracket)
    elif not stack or stack.pop() != matching[bracket]:
        valid = False
        break

valid = valid and not stack
print(valid)  # True
```

```typescript
// TypeScript
const text = "{[()]}";
const matching = new Map<string, string>([
    [")", "("],
    ["]", "["],
    ["}", "{"],
]);
const stack: string[] = [];
let valid = true;

for (const bracket of text) {
    if ("([{ ".trim().includes(bracket)) {
        stack.push(bracket);
    } else if (stack.length === 0 || stack.pop() !== matching.get(bracket)) {
        valid = false;
        break;
    }
}

valid = valid && stack.length === 0;
console.log(valid); // true
```

### Example: breadth-first processing with a queue

This example visits a small tree level by level. Each node enters and leaves the queue once.

```python
# Python
from collections import deque

children = {
    "A": ["B", "C"],
    "B": ["D", "E"],
    "C": [],
    "D": [],
    "E": [],
}
queue = deque(["A"])
order = []

while queue:
    node = queue.popleft()
    order.append(node)
    queue.extend(children[node])

print(order)  # ['A', 'B', 'C', 'D', 'E']
```

```typescript
// TypeScript
const children = new Map<string, string[]>([
    ["A", ["B", "C"]],
    ["B", ["D", "E"]],
    ["C", []],
    ["D", []],
    ["E", []],
]);
const queue: string[] = ["A"];
const order: string[] = [];
let head = 0;

while (head < queue.length) {
    const node = queue[head];
    head += 1;
    order.push(node);
    queue.push(...(children.get(node) ?? []));
}

console.log(order); // ["A", "B", "C", "D", "E"]
```

Both examples take $O(n)$ time and $O(n)$ space in the worst case.

## 4. Operations cheatsheet

| Operation | Python stack | TypeScript stack | Time |
| --- | --- | --- | ---: |
| Create | `stack = []` | `const stack: T[] = []` | $O(1)$ |
| Push | `stack.append(value)` | `stack.push(value)` | $O(1)$ amortized |
| Peek | `stack[-1]` | `stack[stack.length - 1]` | $O(1)$ |
| Pop | `stack.pop()` | `stack.pop()` | $O(1)$ |
| Empty check | `not stack` | `stack.length === 0` | $O(1)$ |
| Length | `len(stack)` | `stack.length` | $O(1)$ |

| Operation | Python deque | TypeScript array + head | Time |
| --- | --- | --- | ---: |
| Create | `queue = deque()` | `const queue: T[] = []; let head = 0` | $O(1)$ |
| Enqueue | `queue.append(value)` | `queue.push(value)` | $O(1)$ amortized |
| Peek front | `queue[0]` | `queue[head]` | $O(1)$ |
| Dequeue | `queue.popleft()` | `const value = queue[head++]` | $O(1)$ |
| Empty check | `not queue` | `head >= queue.length` | $O(1)$ |
| Active length | `len(queue)` | `queue.length - head` | $O(1)$ |
| Add to front | `queue.appendleft(value)` | Use a deque implementation | $O(1)$ with deque |
| Remove from back | `queue.pop()` | `queue.pop()` | $O(1)$ |

## 5. Important considerations

### Check before peeking or removing

An empty stack or queue has no next element. Guard against empty collections unless the problem guarantees that an element exists.

### Do not use `shift()` in large TypeScript loops

Repeated `shift()` calls can make linear processing quadratic. Keep a head index and increment it after reading each queued element.

### Compact long-lived TypeScript queues

A head-index queue retains consumed elements. For a long-lived application, occasionally slice the active suffix when the head becomes large. Competitive-programming queues are usually discarded after one traversal.

### Monotonic structures store useful candidates

A monotonic stack or deque removes values that can no longer contribute to a future answer. Each element is added and removed at most once, which often turns a nested-loop idea into $O(n)$.

### BFS and DFS produce different traversal orders

Use a queue for breadth-first exploration and minimum edge counts in unweighted graphs. Use a stack for depth-first exploration, backtracking order, or explicit recursion simulation.
