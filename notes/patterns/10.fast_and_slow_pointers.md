# Fast and Slow Pointers

## 1. How I think about it

Fast and slow pointers (also called *tortoise and hare*) traverse the same structure at different speeds. The slow pointer moves one step per iteration and the fast pointer moves two. Because the fast pointer covers ground twice as quickly, the two pointers either meet or the fast one reaches the end.

- Odd number of nodes: the fast pointer reaches the last node of the linked list, so the while fast.next part of the loop condition is false, and the loop terminates. 
- Even number of nodes: the fast pointer is None (via the next pointer of the last node), so the while fast part of the loop condition is false, and the loop terminates

Consider using this technique when the input is a linked list (or any structure with a single "next" link) and the question asks about:

- Detecting a cycle.
- Finding the middle node in a single pass.
- Finding the start of a cycle.

```text
Middle of an odd-length list: 1 -> 2 -> 3 -> 4 -> 5 -> None

step 0: S=1  F=1
step 1: S=2  F=3
step 2: S=3  F=5      F.next is None -> stop, S=3 is the middle
```

```text
Middle of an even-length list: 1 -> 2 -> 3 -> 4

step 0: S=1  F=1
step 1: S=2  F=3
step 2: S=3  F=None   -> stop, S=3 is the second middle node
```

## 2. Template

```python
def fastAndSlow(head):
    fast = head
    slow = head
    while fast and fast.next:
        fast = fast.next.next
        slow = slow.next
    return slow
```

## 3. Examples

### 3.1 Detect a cycle

```python
def has_cycle(head):
    slow = fast = head

    while fast and fast.next:
        slow = slow.next
        fast = fast.next.next

        if slow is fast:
            return True

    return False
```

### 3.2 Find the start of a cycle

```python
def detect_cycle_start(head):
    slow = fast = head

    while fast is not None and fast.next is not None:
        slow = slow.next
        fast = fast.next.next

        if slow is fast:
            entry = head
            while entry is not slow:
                entry = entry.next
                slow = slow.next
            return entry

    return None
```

## 4. Complexity

| Problem | Time | Extra space |
| --- | ---: | ---: |
| Cycle detection | $O(n)$ | $O(1)$ |
| Middle node | $O(n)$ | $O(1)$ |
| Cycle start | $O(n)$ | $O(1)$ |

Linked lists, cycles, and "find the middle in one pass" are the signals that bring me back to fast and slow pointers. The technique avoids storing visited nodes in a set, which would cost $O(n)$ space.

## 5. Mistakes I watch for

- Checking `fast.next.next` before confirming that `fast.next` exists.
- Comparing node values instead of node identity; two different nodes can hold the same value.
- Forgetting the second phase when the problem asks for the cycle's start node.
- Assuming the middle is unique for even-length lists; confirm which middle the problem expects.
- Applying the technique to structures without a single forward link, where the pointer movement rules do not apply.
