# Tries and Prefix Trees

## 1. Description and declaration

A trie is a tree for storing strings by their prefixes. Each edge represents a character, and each path from the root represents a prefix. Terminal markers distinguish complete words from prefixes.

Unlike a hash set, a trie can efficiently answer both "does this word exist?" and "does any stored word start with this prefix?".

### Python

```python
class TrieNode:
    def __init__(self):
        self.children = {}
        self.is_word = False

class Trie:
    def __init__(self):
        self.root = TrieNode()

    def insert(self, word):
        node = self.root
        for character in word:
            node = node.children.setdefault(character, TrieNode())
        node.is_word = True

    def search(self, word):
        node = self._find(word)
        return node is not None and node.is_word

    def starts_with(self, prefix):
        return self._find(prefix) is not None

    def _find(self, text):
        node = self.root
        for character in text:
            if character not in node.children:
                return None
            node = node.children[character]
        return node

trie = Trie()
trie.insert("apple")
print(trie.search("apple"))     # True
print(trie.search("app"))       # False
print(trie.starts_with("app"))  # True
```

### TypeScript

```typescript
class TrieNode {
    children = new Map<string, TrieNode>();
    isWord = false;
}

class Trie {
    private root = new TrieNode();

    insert(word: string): void {
        let node = this.root;
        for (const character of word) {
            if (!node.children.has(character)) node.children.set(character, new TrieNode());
            node = node.children.get(character)!;
        }
        node.isWord = true;
    }

    search(word: string): boolean {
        const node = this.find(word);
        return node !== undefined && node.isWord;
    }

    startsWith(prefix: string): boolean {
        return this.find(prefix) !== undefined;
    }

    private find(text: string): TrieNode | undefined {
        let node = this.root;
        for (const character of text) {
            const next = node.children.get(character);
            if (next === undefined) return undefined;
            node = next;
        }
        return node;
    }
}

const trie = new Trie();
trie.insert("apple");
console.log(trie.search("apple"));   // true
console.log(trie.search("app"));     // false
console.log(trie.startsWith("app")); // true
```

## 2. Complexity model

Let $m$ be the length of the word or prefix, and let $S$ be the total number of stored characters.

| Operation | Time | Extra space |
| --- | ---: | ---: |
| Insert word | $O(m)$ | $O(m)$ worst case |
| Search exact word | $O(m)$ | $O(1)$ iterative |
| Search prefix | $O(m)$ | $O(1)$ iterative |
| Delete word | $O(m)$ | $O(m)$ with recursion |
| Enumerate words under prefix | $O(m + r)$ | Output and traversal dependent |
| Store trie | N/A | $O(S)$ nodes worst case |

Here, $r$ is the work needed to traverse and return matching suffixes. Shared prefixes reduce storage, but per-node maps or arrays add overhead.

## 3. Where this fits in my mental model

### When I reach for a trie

- Prefix existence and autocomplete.
- Dictionary lookup with shared prefixes.
- Word Search II on a character grid.
- Finding the shortest dictionary root of a word.
- Maximum XOR queries with a binary trie.
- Lexicographic traversal of stored strings.

| Problem type | Trie advantage | Typical complexity |
| --- | --- | ---: |
| Exact word and prefix search | Traverses characters once | $O(m)$ |
| Autocomplete | Starts traversal at prefix node | $O(m + r)$ |
| Replace words by roots | Stops at first terminal node | $O(m)$ per word |
| Grid dictionary search | Prunes impossible prefixes early | Input-dependent |
| Maximum XOR | Chooses opposite bit greedily | $O(b)$ per number |

### Example: replace words with shortest roots

Once a terminal node is reached, the shortest matching root has been found.

```python
# Python
roots = {"cat", "bat", "rat"}
sentence = "the cattle was rattled by the battery"

result = []
for word in sentence.split():
    replacement = word
    for length in range(1, len(word) + 1):
        prefix = word[:length]
        if prefix in roots:
            replacement = prefix
            break
    result.append(replacement)

print(" ".join(result))  # the cat was rat by the bat
```

```typescript
// TypeScript
const roots = new Set(["cat", "bat", "rat"]);
const sentence = "the cattle was rattled by the battery";

const result = sentence.split(" ").map((word) => {
    for (let length = 1; length <= word.length; length += 1) {
        const prefix = word.slice(0, length);
        if (roots.has(prefix)) return prefix;
    }
    return word;
});

console.log(result.join(" ")); // the cat was rat by the bat
```

The example uses a set for brevity. A trie avoids constructing and hashing every prefix and can stop directly at the first terminal node.

## 4. Operations cheatsheet

| Operation | Core logic | Time |
| --- | --- | ---: |
| Insert | Follow or create each character child | $O(m)$ |
| Exact search | Follow all characters, then check terminal marker | $O(m)$ |
| Prefix search | Follow all characters | $O(m)$ |
| Delete | Unmark terminal and prune unused nodes | $O(m)$ |
| Autocomplete | Find prefix node, then DFS descendants | $O(m + r)$ |
| Count prefix matches | Store subtree count in each node | $O(m)$ query |
| Alphabet-array child | Index by character code | $O(1)$ child access |
| Map child | Lookup character key | $O(1)$ average child access |

## 5. Important considerations

### Prefixes are not automatically complete words

After inserting `apple`, the prefix `app` exists but is not an exact match until its terminal marker is set.

### Child representation affects memory

A fixed child array is fast for a small known alphabet but reserves unused slots. A map stores only existing edges and works well for sparse or large alphabets.

### Tries can consume more memory than hash sets

Each node stores metadata and child references. I use a hash set when I only need exact membership, and a trie when prefix behavior or character-by-character pruning adds enough value to justify the extra structure.

### Deletion must preserve shared prefixes

Removing `car` must not remove nodes still needed by `card`. Prune a node only when it is not terminal and has no children.

### Normalize input consistently

Case, accents, and Unicode representation affect character paths. Apply the same normalization during insertion and lookup when the problem treats variants as equivalent.
