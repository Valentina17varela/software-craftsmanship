# Trees

## 1. Description and declaration

A tree is a hierarchical collection of nodes connected by edges. It has one root and contains no cycles. Every node except the root has exactly one parent.

A binary tree allows at most two children per node. A binary search tree (BST) additionally keeps smaller values in the left subtree and larger values in the right subtree.

### Python

```python
class TreeNode:
    def __init__(self, value, left=None, right=None):
        self.value = value
        self.left = left
        self.right = right

root = TreeNode(2, TreeNode(1), TreeNode(3))
print(root.left.value)  # 1
```

### TypeScript

```typescript
class TreeNode<T> {
    constructor(
        public value: T,
        public left: TreeNode<T> | null = null,
        public right: TreeNode<T> | null = null,
    ) {}
}

const root = new TreeNode(2, new TreeNode(1), new TreeNode(3));
console.log(root.left?.value); // 1
```

### Key terminology

- **Root:** the first node in the tree.
- **Parent and child:** nodes directly connected on adjacent levels.
- **Leaf:** a node without children.
- **Depth:** number of edges from the root to a node.
- **Height:** maximum number of edges from a node to a leaf.
- **Subtree:** a node and all its descendants.
- **Balanced tree:** a tree whose height stays close to $\log n$.

## 2. Complexity model

Throughout this document, $n$ is the number of nodes and $h$ is the tree height.

### General rules

1. A full traversal visits every node and costs $O(n)$.
2. Search, insertion, and deletion in a BST cost $O(h)$.
3. A balanced BST has $h = O(\log n)$.
4. A skewed BST can have $h = O(n)$.
5. Recursive depth-first traversal uses $O(h)$ call-stack space.
6. Breadth-first traversal may store $O(n)$ nodes at the widest level.

### Complexity summary

| Operation | Balanced BST | Worst-case BST | Extra space |
| --- | ---: | ---: | ---: |
| Search | $O(\log n)$ | $O(n)$ | $O(1)$ iterative |
| Insert | $O(\log n)$ | $O(n)$ | $O(1)$ iterative |
| Delete | $O(\log n)$ | $O(n)$ | $O(1)$ iterative |
| Minimum or maximum | $O(\log n)$ | $O(n)$ | $O(1)$ |
| DFS traversal | $O(n)$ | $O(n)$ | $O(h)$ |
| BFS traversal | $O(n)$ | $O(n)$ | $O(n)$ |

## 3. Where this fits in my mental model

### When I reach for trees

I reach for a tree when the problem contains hierarchical relationships or requires:

- Traversing parent-child relationships.
- Computing subtree values.
- Finding paths, ancestors, depth, or height.
- Searching ordered data in a BST.
- Processing expressions or nested structures.
- Representing ranges with segment trees or Fenwick trees.
- Maintaining priorities with a heap.
- Answering ancestor queries with binary lifting.

### Common problem patterns

| Problem type | Recommended technique | Typical complexity |
| --- | --- | ---: |
| Tree traversal | DFS or BFS | $O(n)$ |
| Maximum depth | Postorder DFS | $O(n)$ |
| Level-order traversal | BFS | $O(n)$ |
| Validate BST | DFS with lower/upper bounds | $O(n)$ |
| Lowest common ancestor | DFS or binary lifting | $O(n)$ or $O(\log n)$ query |
| Subtree aggregation | Postorder DFS | $O(n)$ |
| Range queries | Segment tree | $O(\log n)$ per query |
| Priority processing | Heap | $O(\log n)$ insertion/removal |

### Example: depth-first traversals

Traversal order depends on when the current node is processed:

- Preorder: node, left, right.
- Inorder: left, node, right. In a BST, this produces sorted values.
- Postorder: left, right, node.

```python
# Python
class TreeNode:
    def __init__(self, value, left=None, right=None):
        self.value = value
        self.left = left
        self.right = right

root = TreeNode(2, TreeNode(1), TreeNode(3))


def inorder(node):
    result = []

    def traverse(current):
        if current is None:
            return
        traverse(current.left)
        result.append(current.value)
        traverse(current.right)

    traverse(node)
    return result


print(inorder(root))  # [1, 2, 3]
```

```typescript
// TypeScript
class TreeNode<T> {
    constructor(
        public value: T,
        public left: TreeNode<T> | null = null,
        public right: TreeNode<T> | null = null,
    ) {}
}

const root = new TreeNode(2, new TreeNode(1), new TreeNode(3));

function inorder(node: TreeNode<number> | null): number[] {
    const result: number[] = [];

    function traverse(current: TreeNode<number> | null): void {
        if (current === null) return;
        traverse(current.left);
        result.push(current.value);
        traverse(current.right);
    }

    traverse(node);
    return result;
}

console.log(inorder(root)); // [1, 2, 3]
```

### Example: level-order traversal

A queue lets me visit every node at one depth before moving to the next.

```python
# Python
from collections import deque

class TreeNode:
    def __init__(self, value, left=None, right=None):
        self.value = value
        self.left = left
        self.right = right

root = TreeNode(1, TreeNode(2, TreeNode(4)), TreeNode(3))
queue = deque([root])
levels = []

while queue:
    level = []
    for _ in range(len(queue)):
        node = queue.popleft()
        level.append(node.value)
        if node.left:
            queue.append(node.left)
        if node.right:
            queue.append(node.right)
    levels.append(level)

print(levels)  # [[1], [2, 3], [4]]
```

```typescript
// TypeScript
class TreeNode<T> {
    constructor(
        public value: T,
        public left: TreeNode<T> | null = null,
        public right: TreeNode<T> | null = null,
    ) {}
}

const root = new TreeNode(1, new TreeNode(2, new TreeNode(4)), new TreeNode(3));
const queue: TreeNode<number>[] = [root];
const levels: number[][] = [];
let head = 0;

while (head < queue.length) {
    const levelEnd = queue.length;
    const level: number[] = [];

    while (head < levelEnd) {
        const node = queue[head++];
        level.push(node.value);
        if (node.left !== null) queue.push(node.left);
        if (node.right !== null) queue.push(node.right);
    }
    levels.push(level);
}

console.log(levels); // [[1], [2, 3], [4]]
```

Both traversals take $O(n)$ time. DFS uses $O(h)$ stack space; BFS uses up to $O(n)$ queue space.

## 4. Operations cheatsheet

| Goal | Python | TypeScript | Complexity |
| --- | --- | --- | ---: |
| Create node | `TreeNode(value)` | `new TreeNode(value)` | $O(1)$ |
| Read left child | `node.left` | `node.left` | $O(1)$ |
| Read right child | `node.right` | `node.right` | $O(1)$ |
| Leaf check | `not node.left and not node.right` | `!node.left && !node.right` | $O(1)$ |
| Preorder | Process, left, right | Process, left, right | $O(n)$ |
| Inorder | Left, process, right | Left, process, right | $O(n)$ |
| Postorder | Left, right, process | Left, right, process | $O(n)$ |
| Level order | `deque` BFS | Array + head-index BFS | $O(n)$ |
| BST search | Compare and choose one child | Compare and choose one child | $O(h)$ |
| Compute height | `1 + max(left, right)` | `1 + Math.max(left, right)` | $O(n)$ |

## 5. Important considerations

### A binary tree is not automatically a BST

A binary tree only limits each node to two children. BST ordering is an additional invariant and must hold for every descendant, not only immediate children.

### Tree complexity depends on height

Calling BST operations $O(\log n)$ is correct only when the tree is balanced. A sorted insertion order can produce a chain with $O(n)$ operations in an unbalanced BST.

### How I choose traversal order

Preorder is useful for copying or serialization, inorder for ordered BST values, postorder for subtree calculations, and level order for depth-by-depth processing.

### Recursive DFS can overflow

A skewed tree can make recursion depth $O(n)$. I switch to an explicit stack when the depth may exceed the language's recursion limit.

### Trees are often given implicitly

Heaps, segment trees, and Fenwick trees are usually stored in arrays rather than node objects. For a zero-based binary heap, children of index $i$ are at $2i + 1$ and $2i + 2$.
