# Graphs

## 1. Description and declaration

A graph is a collection of vertices connected by edges. Graphs model relationships such as roads, dependencies, social connections, networks, and state transitions.

Graphs may be directed or undirected, weighted or unweighted, connected or disconnected, and cyclic or acyclic.

### Adjacency list in Python

```python
graph = {
    "A": ["B", "C"],
    "B": ["A", "D"],
    "C": ["A"],
    "D": ["B"],
}

print(graph["A"])  # ['B', 'C']
```

### Adjacency list in TypeScript

```typescript
const graph = new Map<string, string[]>([
    ["A", ["B", "C"]],
    ["B", ["A", "D"]],
    ["C", ["A"]],
    ["D", ["B"]],
]);

console.log(graph.get("A")); // ["B", "C"]
```

### Key terminology

- **Vertex/node:** an entity in the graph.
- **Edge:** a connection between two vertices.
- **Directed edge:** a one-way connection from one vertex to another.
- **Weight:** a cost, distance, or capacity assigned to an edge.
- **Path:** a sequence of connected vertices.
- **Cycle:** a path that returns to its starting vertex.
- **Degree:** number of edges incident to a vertex.
- **Connected component:** a maximal group of mutually reachable vertices in an undirected graph.

## 2. Complexity model

Throughout this document, $V$ is the number of vertices and $E$ is the number of edges.

### Representation tradeoffs

| Operation | Adjacency list | Adjacency matrix |
| --- | ---: | ---: |
| Storage | $O(V + E)$ | $O(V^2)$ |
| Add edge | $O(1)$ | $O(1)$ |
| Check specific edge | $O(degree(u))$ | $O(1)$ |
| Iterate neighbors | $O(degree(u))$ | $O(V)$ |
| BFS or DFS | $O(V + E)$ | $O(V^2)$ |

Adjacency lists are my usual default for sparse graphs. Matrices become interesting when the graph is dense or constant-time edge lookup matters.

### Common algorithm complexities

| Algorithm | Purpose | Time complexity | Extra space |
| --- | --- | ---: | ---: |
| BFS | Unweighted shortest path | $O(V + E)$ | $O(V)$ |
| DFS | Reachability and structure | $O(V + E)$ | $O(V)$ |
| Topological sort | Order a DAG | $O(V + E)$ | $O(V)$ |
| Dijkstra with heap | Non-negative weighted paths | $O((V + E) \log V)$ | $O(V + E)$ |
| Bellman-Ford | Paths with negative edges | $O(VE)$ | $O(V)$ |
| Floyd-Warshall | All-pairs shortest paths | $O(V^3)$ | $O(V^2)$ |
| Union-Find | Connectivity updates | Nearly $O(1)$ amortized | $O(V)$ |

## 3. Where this fits in my mental model

### When I reach for graphs

Model a problem as a graph when it describes states or entities connected by valid transitions. Typical signals include:

- Cities connected by roads.
- Courses with prerequisites.
- People connected by relationships.
- Grid cells connected to neighboring cells.
- Transformations from one state to another.
- Dependencies that require an execution order.
- Networks with costs, capacities, or directions.

### Choosing an algorithm

| Problem type | Recommended technique | Important condition |
| --- | --- | --- |
| Reachability | BFS or DFS | Any graph |
| Fewest edges from a source | BFS | Unweighted graph |
| Lowest weighted cost | Dijkstra | No negative edge weights |
| Negative weighted edges | Bellman-Ford | Detects negative cycles |
| Dependency ordering | Topological sort | Directed acyclic graph |
| Connected components | DFS, BFS, or Union-Find | Usually undirected graph |
| Detect undirected cycle | DFS with parent or Union-Find | Undirected graph |
| Detect directed cycle | DFS colors or Kahn's algorithm | Directed graph |
| Minimum spanning tree | Kruskal or Prim | Weighted undirected graph |
| All-pairs shortest path | Floyd-Warshall | Usually small $V$ |

### Example: shortest path with BFS

In an unweighted graph, BFS explores nodes by distance. The first time a node is reached gives its minimum number of edges from the start.

```python
# Python
from collections import deque

graph = {
    "A": ["B", "C"],
    "B": ["D"],
    "C": ["D", "E"],
    "D": ["F"],
    "E": ["F"],
    "F": [],
}
start = "A"
queue = deque([start])
distance = {start: 0}

while queue:
    node = queue.popleft()
    for neighbor in graph[node]:
        if neighbor not in distance:
            distance[neighbor] = distance[node] + 1
            queue.append(neighbor)

print(distance["F"])  # 3
```

```typescript
// TypeScript
const graph = new Map<string, string[]>([
    ["A", ["B", "C"]],
    ["B", ["D"]],
    ["C", ["D", "E"]],
    ["D", ["F"]],
    ["E", ["F"]],
    ["F", []],
]);
const start = "A";
const queue: string[] = [start];
const distance = new Map<string, number>([[start, 0]]);
let head = 0;

while (head < queue.length) {
    const node = queue[head++];
    for (const neighbor of graph.get(node) ?? []) {
        if (!distance.has(neighbor)) {
            distance.set(neighbor, distance.get(node)! + 1);
            queue.push(neighbor);
        }
    }
}

console.log(distance.get("F")); // 3
```

### Example: connected components with DFS

I start a new traversal from every unvisited vertex; the number of traversals is the number of connected components.

```python
# Python
graph = {
    0: [1],
    1: [0],
    2: [3],
    3: [2],
    4: [],
}
visited = set()
components = 0

for start in graph:
    if start in visited:
        continue

    components += 1
    stack = [start]
    visited.add(start)

    while stack:
        node = stack.pop()
        for neighbor in graph[node]:
            if neighbor not in visited:
                visited.add(neighbor)
                stack.append(neighbor)

print(components)  # 3
```

```typescript
// TypeScript
const graph = new Map<number, number[]>([
    [0, [1]],
    [1, [0]],
    [2, [3]],
    [3, [2]],
    [4, []],
]);
const visited = new Set<number>();
let components = 0;

for (const start of graph.keys()) {
    if (visited.has(start)) continue;

    components += 1;
    const stack: number[] = [start];
    visited.add(start);

    while (stack.length > 0) {
        const node = stack.pop()!;
        for (const neighbor of graph.get(node) ?? []) {
            if (!visited.has(neighbor)) {
                visited.add(neighbor);
                stack.push(neighbor);
            }
        }
    }
}

console.log(components); // 3
```

Both algorithms take $O(V + E)$ time and $O(V)$ extra space.

## 4. Operations cheatsheet

| Goal | Python | TypeScript | Complexity |
| --- | --- | --- | ---: |
| Empty adjacency list | `graph = {}` | `new Map<T, T[]>()` | $O(1)$ |
| Add vertex | `graph.setdefault(node, [])` | `graph.set(node, [])` | $O(1)$ average |
| Add directed edge | `graph[u].append(v)` | `graph.get(u)!.push(v)` | $O(1)$ amortized |
| Add undirected edge | Add both `u -> v` and `v -> u` | Add both directions | $O(1)$ amortized |
| Read neighbors | `graph[node]` | `graph.get(node) ?? []` | $O(1)$ average |
| BFS | `deque` plus visited set | Array + head plus visited set | $O(V + E)$ |
| Iterative DFS | Stack plus visited set | Stack plus visited set | $O(V + E)$ |
| Track visited | `set()` | `new Set<T>()` | $O(V)$ space |
| Store distance | `dict` | `Map<T, number>` | $O(V)$ space |
| Store parent | `dict` | `Map<T, T>` | $O(V)$ space |

## 5. Important considerations

### Mark nodes visited when enqueuing

In BFS, mark a node as visited when it enters the queue, not when it leaves. Otherwise, multiple neighbors may enqueue the same node and waste time and memory.

### Undirected edges must be added twice

An undirected edge between `u` and `v` requires both `u -> v` and `v -> u` in an adjacency list.

### Graphs may be disconnected

A traversal from one start visits only its reachable component. To process the entire graph, I loop through all vertices and begin a new traversal at each unvisited one.

### How I choose a shortest-path algorithm

BFS is correct for unweighted graphs or equal edge weights. Dijkstra requires non-negative weights. Negative edges require algorithms such as Bellman-Ford; Dijkstra may return an incorrect result.

### Distinguish a node's parent from a cycle

In an undirected DFS, the edge back to the immediate parent is not a cycle. In directed graphs, I use recursion-state colors or indegrees because parent tracking alone is insufficient.

### Grids are implicit graphs

A grid does not need an explicit adjacency list. Generate valid neighboring cells during traversal to keep storage at $O(rows \cdot columns)$ rather than materializing every edge.
