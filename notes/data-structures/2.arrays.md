# Arrays

## 1. Description and declaration

An array is an ordered, index-based collection of values. Arrays are useful when elements must be stored in sequence, accessed by position, traversed, sorted, or processed with techniques such as two pointers, sliding windows, and prefix sums.

In Python, the general-purpose dynamic array is called a `list`. In TypeScript, it is represented by `Array<T>` or `T[]`. Both structures can grow and shrink at runtime.

### Python

```python
numbers = [10, 20, 30]
first = numbers[0]
numbers[1] = 25

print(numbers)  # [10, 25, 30]
print(first)    # 10
```

### TypeScript

```typescript
const numbers: number[] = [10, 20, 30];
const first: number = numbers[0];
numbers[1] = 25;

console.log(numbers); // [10, 25, 30]
console.log(first);   // 10
```

### Key properties

- Arrays preserve insertion order.
- Indexes are zero-based.
- Duplicate values are allowed.
- Elements can be read and replaced by index.
- Python lists and TypeScript arrays are mutable and dynamically sized.
- Appending at the end is amortized $O(1)$.
- Inserting or removing near the beginning requires shifting elements and is $O(n)$.
- Python supports negative indexes directly. For broad TypeScript compatibility, use `items[items.length - 1]` for the last element.

```python
# Python: the list is modified in place
numbers = [10, 20, 30]
numbers[0] = 5
numbers.append(40)

print(numbers)  # [5, 20, 30, 40]
print(numbers[-1])  # 40
```

```typescript
// TypeScript: the array is modified in place
const numbers: number[] = [10, 20, 30];
numbers[0] = 5;
numbers.push(40);

console.log(numbers);        // [5, 20, 30, 40]
console.log(numbers[numbers.length - 1]); // 40
```

## 2. Complexity model

An array does not have one general time complexity. The cost depends mainly on the position of the operation and whether elements must be shifted, copied, traversed, or sorted.

Throughout this document:

- $n$ is the number of elements in the array.
- $m$ is the number of elements in another array.
- $k$ is the number of elements copied into a result.

### General rules

1. Reading the length or accessing an element by index is $O(1)$.
2. Traversing or searching an unsorted array is $O(n)$.
3. Appending or removing at the end is amortized $O(1)$.
4. Inserting or removing at the beginning or middle is $O(n)$ because elements must shift.
5. Slicing or copying $k$ elements requires $O(k)$ time and space.
6. Comparison-based sorting requires $O(n \log n)$ time in the general case.

### Complexity summary

| Operation | Time complexity | Extra space | Reason |
| --- | ---: | ---: | --- |
| Length | $O(1)$ | $O(1)$ | The length is stored by the runtime. |
| Access by index | $O(1)$ | $O(1)$ | The position is addressed directly. |
| Replace by index | $O(1)$ | $O(1)$ | No elements need to shift. |
| Full traversal | $O(n)$ | $O(1)$ | Every element is visited once. |
| Search by value | $O(n)$ | $O(1)$ | The value may be at the final position or absent. |
| Append to end | Amortized $O(1)$ | $O(1)$ amortized | Occasional resizing copies existing elements. |
| Remove from end | $O(1)$ | $O(1)$ | No remaining elements shift. |
| Insert at beginning or middle | $O(n)$ | $O(1)$ | Later elements shift right. |
| Remove from beginning or middle | $O(n)$ | $O(1)$ | Later elements shift left. |
| Slice or shallow copy | $O(k)$ | $O(k)$ | The selected references or values are copied. |
| Concatenate | $O(n + m)$ | $O(n + m)$ | Both inputs are copied into a new array. |
| Reverse in place | $O(n)$ | $O(1)$ | Elements are swapped from both ends. |
| Sort in place | Typically $O(n \log n)$; runtime-dependent | Runtime-dependent | The exact algorithm and auxiliary space depend on the runtime. |

These are practical asymptotic bounds for Python lists and dense TypeScript arrays. Exact memory use and implementation details can vary by runtime.

## 3. Competitive programming use cases

### When to use arrays

Use an array when the problem works with an ordered collection and requires one or more of these operations:

- Accessing or updating elements by index.
- Traversing values from left to right or in reverse.
- Sorting values before processing them.
- Maintaining a fixed-size or variable-size window.
- Computing prefix sums or suffix values.
- Comparing elements with two pointers.
- Representing frequencies when keys belong to a small integer range.
- Building dynamic programming tables, matrices, adjacency lists, heaps, or stacks.

### Common problem patterns

| Problem type | Recommended technique | Typical complexity |
| --- | --- | ---: |
| Pair in a sorted array | Two pointers | $O(n)$ |
| Contiguous subarray condition | Sliding window | $O(n)$ |
| Range sum queries | Prefix sums | $O(n)$ preprocessing, $O(1)$ query |
| Maximum subarray sum | Kadane's algorithm | $O(n)$ |
| Search in sorted data | Binary search | $O(\log n)$ |
| Merge sorted arrays | Two pointers | $O(n + m)$ |
| Count values in a small range | Frequency array | $O(n + r)$ |
| Next greater element | Monotonic stack | $O(n)$ |
| Top or smallest values | Heap | $O(n \log k)$ |
| Interval problems | Sort and scan | $O(n \log n)$ |
| Grid traversal | Matrix with DFS or BFS | $O(rows \cdot columns)$ |
| Subproblem optimization | Dynamic programming array | Problem-dependent |

### Example: prefix sums

Use prefix sums when you need to calculate the sum of many ranges in the same array.

`prefix[i]` stores the sum of the first `i` elements. The initial `0` represents the sum before the array starts:

| Index `i` | Elements included | `prefix[i]` |
| ---: | --- | ---: |
| 0 | None | 0 |
| 1 | `2` | 2 |
| 2 | `2 + 4` | 6 |
| 3 | `2 + 4 + 1` | 7 |
| 4 | `2 + 4 + 1 + 7` | 14 |

To get the sum from inclusive index `left` to inclusive index `right`, use:

$$
rangeSum = prefix[right + 1] - prefix[left]
$$

For indexes `1` through `3`, the expected sum is $4 + 1 + 7 = 12$. We calculate `prefix[4] - prefix[1]`, which is $14 - 2 = 12$. The subtraction removes every value before `left`.

```python
# Python
numbers = [2, 4, 1, 7]
prefix = [0]

for number in numbers:
    prefix.append(prefix[-1] + number)

left, right = 1, 3
range_sum = prefix[right + 1] - prefix[left]

print(prefix)     # [0, 2, 6, 7, 14]
print(range_sum)  # 12: 4 + 1 + 7
```

```typescript
// TypeScript
const numbers: number[] = [2, 4, 1, 7];
const prefix: number[] = [0];

for (const number of numbers) {
    prefix.push(prefix[prefix.length - 1] + number);
}

const left = 1;
const right = 3;
const rangeSum = prefix[right + 1] - prefix[left];

console.log(prefix);   // [0, 2, 6, 7, 14]
console.log(rangeSum); // 12: 4 + 1 + 7
```

Building the prefix array costs $O(n)$ time and $O(n)$ space. Each range query then costs $O(1)$.

### Example: two pointers

Use two pointers when a sorted array lets you make a decision based on both ends. In this example, the goal is to find two numbers whose sum equals `target`.

- If the current sum is too small, move `left` right to increase it.
- If the current sum is too large, move `right` left to decrease it.
- If the sum equals the target, the pair has been found.

```python
# Python
numbers = [1, 2, 4, 6, 10]
target = 8
left = 0
right = len(numbers) - 1
pair = None

while left < right:
    current_sum = numbers[left] + numbers[right]

    if current_sum == target:
        pair = (numbers[left], numbers[right])
        break
    if current_sum < target:
        left += 1
    else:
        right -= 1

print(pair)  # (2, 6)
```

```typescript
// TypeScript
const numbers: number[] = [1, 2, 4, 6, 10];
const target = 8;
let left = 0;
let right = numbers.length - 1;
let pair: [number, number] | null = null;

while (left < right) {
    const currentSum = numbers[left] + numbers[right];

    if (currentSum === target) {
        pair = [numbers[left], numbers[right]];
        break;
    }
    if (currentSum < target) {
        left += 1;
    } else {
        right -= 1;
    }
}

console.log(pair); // [2, 6]
```

Each pointer moves at most $n$ positions, so the algorithm takes $O(n)$ time and $O(1)$ extra space. If the input is not sorted, sorting it first costs $O(n \log n)$.

### Example: fixed-size sliding window

Use a sliding window for contiguous subarrays. In this example, the goal is to find the maximum sum among all subarrays of length `window_size = 3`.

Start with the first window. Each time the window moves one position, add the incoming value and subtract the outgoing value instead of summing all three elements again.

```python
# Python
numbers = [2, 1, 5, 1, 3, 2]
window_size = 3
window_sum = sum(numbers[:window_size])
max_sum = window_sum

for right in range(window_size, len(numbers)):
    incoming = numbers[right]
    outgoing = numbers[right - window_size]
    window_sum += incoming - outgoing
    max_sum = max(max_sum, window_sum)

print(max_sum)  # 9: [5, 1, 3]
```

```typescript
// TypeScript
const numbers: number[] = [2, 1, 5, 1, 3, 2];
const windowSize = 3;
let windowSum = numbers
    .slice(0, windowSize)
    .reduce((sum, number) => sum + number, 0);
let maxSum = windowSum;

for (let right = windowSize; right < numbers.length; right += 1) {
    const incoming = numbers[right];
    const outgoing = numbers[right - windowSize];
    windowSum += incoming - outgoing;
    maxSum = Math.max(maxSum, windowSum);
}

console.log(maxSum); // 9: [5, 1, 3]
```

The initial window takes $O(k)$ time and the remaining traversal takes $O(n - k)$, resulting in $O(n)$ time and $O(1)$ extra space.

### When not to use an array directly

Choose a different data structure when the dominant operation does not match array strengths:

- Use a `set` for frequent membership checks when order and duplicates are unimportant.
- Use a hash map for fast lookup by arbitrary keys.
- Use a deque or queue for frequent insertion and removal at the beginning.
- Use a linked structure only when frequent middle insertion or removal is required and direct node references are available.
- Use a heap when only the smallest or largest element must be retrieved repeatedly.

## 4. Operations cheatsheet

Assume $n$ is the array length, $m$ is the length of another array, and $k$ is the number of elements in the result.

| Operation | Python | TypeScript | Time | Extra space |
| --- | --- | --- | ---: | ---: |
| Declare | `items = [1, 2, 3]` | `const items: number[] = [1, 2, 3]` | $O(n)$ | $O(n)$ |
| Empty array | `items = []` | `const items: number[] = []` | $O(1)$ | $O(1)$ |
| Length | `len(items)` | `items.length` | $O(1)$ | $O(1)$ |
| Access by index | `items[index]` | `items[index]` | $O(1)$ | $O(1)$ |
| Last element | `items[-1]` | `items[items.length - 1]` | $O(1)$ | $O(1)$ |
| Replace by index | `items[index] = value` | `items[index] = value` | $O(1)$ | $O(1)$ |
| Append to end | `items.append(value)` | `items.push(value)` | Amortized $O(1)$ | $O(1)$ amortized |
| Remove from end | `items.pop()` | `items.pop()` | $O(1)$ | $O(1)$ |
| Insert at index | `items.insert(index, value)` | `items.splice(index, 0, value)` | $O(n)$ | $O(1)$ |
| Remove at index | `items.pop(index)` | `items.splice(index, 1)` | $O(n)$ | $O(1)$ |
| Remove first value | `items.remove(value)` | `const i = items.indexOf(value); if (i >= 0) items.splice(i, 1)` | $O(n)$ | $O(1)$ |
| Remove from beginning | `items.pop(0)` | `items.shift()` | $O(n)$ | $O(1)$ |
| Add to beginning | `items.insert(0, value)` | `items.unshift(value)` | $O(n)$ | $O(1)$ |
| Contains value | `value in items` | `items.includes(value)` | $O(n)$ | $O(1)$ |
| Find first index | `items.index(value)` | `items.indexOf(value)` | $O(n)$ | $O(1)$ |
| Slice | `items[start:end]` | `items.slice(start, end)` | $O(k)$ | $O(k)$ |
| Shallow copy | `items.copy()` | `[...items]` | $O(n)$ | $O(n)$ |
| Concatenate | `left + right` | `[...left, ...right]` | $O(n + m)$ | $O(n + m)$ |
| Reverse in place | `items.reverse()` | `items.reverse()` | $O(n)$ | $O(1)$ |
| Reversed copy | `items[::-1]` | `[...items].reverse()` | $O(n)$ | $O(n)$ |
| Sort ascending | `items.sort()` | `items.sort((a, b) => a - b)` | $O(n \log n)$ | Runtime-dependent |
| Sorted copy | `sorted(items)` | `[...items].sort((a, b) => a - b)` | $O(n \log n)$ typical | $O(n)$ plus sort workspace |
| Sum | `sum(items)` | `items.reduce((sum, x) => sum + x, 0)` | $O(n)$ | $O(1)$ |
| Minimum | `min(items)` | `Math.min(...items)` | $O(n)$ | Runtime-dependent |
| Maximum | `max(items)` | `Math.max(...items)` | $O(n)$ | Runtime-dependent |
| Transform | `[f(x) for x in items]` | `items.map(f)` | $O(n)$ | $O(n)$ |
| Filter | `[x for x in items if condition]` | `items.filter(condition)` | $O(n)$ | $O(n)$ |
| Any match | `any(condition for x in items)` | `items.some(condition)` | $O(n)$ worst case | $O(1)$ |
| All match | `all(condition for x in items)` | `items.every(condition)` | $O(n)$ worst case | $O(1)$ |
| Iterate with index | `for i, x in enumerate(items):` | `items.forEach((x, i) => ...)` | $O(n)$ | $O(1)$ |
| Join as string | `separator.join(map(str, items))` | `items.join(separator)` | $O(n)$ plus output size | $O(n)$ plus output size |

### Quick examples

```python
# Python
numbers = [5, 2, 8, 2]
numbers.append(10)
numbers[0] = 4
ascending = sorted(numbers)
even_numbers = [number for number in numbers if number % 2 == 0]

print(numbers)       # [4, 2, 8, 2, 10]
print(ascending)     # [2, 2, 4, 8, 10]
print(even_numbers)  # [4, 2, 8, 2, 10]
```

```typescript
// TypeScript
const numbers: number[] = [5, 2, 8, 2];
numbers.push(10);
numbers[0] = 4;
const ascending: number[] = [...numbers].sort((a, b) => a - b);
const evenNumbers: number[] = numbers.filter((number) => number % 2 === 0);

console.log(numbers);     // [4, 2, 8, 2, 10]
console.log(ascending);   // [2, 2, 4, 8, 10]
console.log(evenNumbers); // [4, 2, 8, 2, 10]
```

**Sorting difference:** Python sorts numbers numerically by default. TypeScript's `Array.sort()` converts elements to strings unless a comparator is provided, so numeric arrays should use `(a, b) => a - b`.

## 5. Important considerations

### Arrays are mutable

Assigning an array to another variable does not create an independent copy. Both variables reference the same collection.

```python
# Python
original = [1, 2, 3]
alias = original
copy = original.copy()

alias[0] = 9

print(original)  # [9, 2, 3]
print(copy)      # [1, 2, 3]
```

```typescript
// TypeScript
const original: number[] = [1, 2, 3];
const alias: number[] = original;
const copy: number[] = [...original];

alias[0] = 9;

console.log(original); // [9, 2, 3]
console.log(copy);     // [1, 2, 3]
```

### Copies are shallow

Methods such as Python's `.copy()` and TypeScript's spread syntax copy the outer array only. Nested arrays and objects remain shared references.

### Avoid removing from the beginning repeatedly

Python's `pop(0)` and TypeScript's `shift()` are $O(n)$ because all remaining elements move. For queue behavior, use `collections.deque` in Python. In TypeScript competitive programming, keep a head index instead of repeatedly calling `shift()`.

### Distinguish mutating and non-mutating methods

Methods such as `append`, `push`, `pop`, `reverse`, `sort`, and `splice` modify the original array. Slicing, spreading, `sorted`, `map`, and `filter` create new arrays. Modern ES2023 runtimes also provide non-mutating `toSorted` and `toReversed` methods.

### Sort numbers with a comparator in TypeScript

Without a comparator, TypeScript and JavaScript sort values as strings. For example, `[2, 10].sort()` produces `[10, 2]`. Use `numbers.sort((a, b) => a - b)` for ascending numeric order and `(a, b) => b - a` for descending order.

### Avoid spread with very large arrays in `Math.min` and `Math.max`

`Math.min(...items)` and `Math.max(...items)` can exceed the runtime's argument limit for large inputs. A loop or `reduce` is safer when competitive-programming constraints are large.
