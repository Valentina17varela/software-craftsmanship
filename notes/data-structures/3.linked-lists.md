# Linked Lists

## 1. Description and declaration

A linked list is a sequence of nodes. Each node stores a value and a reference to the next node. Unlike an array, linked-list nodes do not need contiguous memory and cannot be accessed directly by index.

### Python

```python
class ListNode:
    def __init__(self, value, next_node=None):
        self.value = value
        self.next = next_node

head = ListNode(10, ListNode(20, ListNode(30)))
print(head.next.value)  # 20
```

### TypeScript

```typescript
class ListNode<T> {
    constructor(
        public value: T,
        public next: ListNode<T> | null = null,
    ) {}
}

const head = new ListNode(10, new ListNode(20, new ListNode(30)));
console.log(head.next?.value); // 20
```

### Key properties

- Nodes are connected through references.
- Sequential access is required; indexing is not constant time.
- Insertion or removal after a known node is $O(1)$.
- Finding a value or position is $O(n)$.
- A singly linked list points only to the next node.
- A doubly linked list also points to the previous node.
- The final node points to `None` in Python or `null` in TypeScript.

## Basic operations

### Traversing a Linked List
When traversing a linked list, we initialize a pointer current that starts at the head node of the linked list and follows next pointers until it is None. This allows us to visit each node in the linked list, and perform operations such as finding the length of the linked list.

```python
def findLength(head):
    length = 0
    current = head
    while current:
        length += 1
        current = current.next
    return length
```

### Deleting a Node With a Given Target
We need a reference to both the node we want to delete, and the node right before it.
We'll keep two pointers, curr and prev, and update curr until it reaches the target node, or None. We'll also update prev to be the node before curr at each step. When curr reaches the target node, we can delete it by setting prev.next = curr.next

```python
def deleteNode(head, target):
    if head.val == target:
        return head.next
    
    prev = None
    curr = head
    
    while curr:
        if curr.val == target:
            prev.next = curr.next
            break
        prev = curr
        curr = curr.next
    
    return head
```

### Reversing a Linked List

> Time Complexity: The time complexity of this algorithm is O(n) where n is the number of nodes in the linked list. The algorithm iterates through each node in the linked list once.

> Space Complexity: The space complexity of this algorithm is O(1) since we only use three pointers to reverse the linked list regardless of the number of nodes in the linked list.

Reversing a linked list involves changing the direction of the next pointers in a linked list so the last node becomes the head of the reversed linked list.
The algorithm for reversing a linked list is an iterative algorithm which involves 3 pointers:
- current:  points to the node we are currently reversing.
- prev: is the last node that was reversed, and also the node that current.next will point to after reversing.
- next_: is the next node we will reverse. We need a pointer to this node before we overwrite the current.next so we can continue reversing the list in the next iteration.
When the iteration completes, current will be None, and prev will be the new head of the linked list.

```python
def reverse(head):
    prev = None
    current = head
    while current:
        next_ = current.next
        current.next = prev
        prev = current
        current = next_
    return prev
```

### Merging Two Linked Lists

> Time Complexity: O(n + m) where n and m are the number of nodes in the two input linked lists. The algorithm iterates through each node in the two linked lists once.

> Space Complexity: O(1) We only use a constant amount of space to merge the two linked lists regardless of the number of nodes. This is because we are modifying the next pointers of the input linked lists, rather than creating new nodes.

We are given the heads of two sorted linked lists, l1 and l2, and we need to return the head of a new linked list that contains all the nodes from the two input linked lists in sorted order.

To merge two sorted linked lists, we start by determining the head of the merged linked list by comparing the values of l1 and l2, and setting the head to the smaller of the two nodes. We then advance l1 = l1.next or l2 = l2.next depending on which node we chose as the head of the merged linked list.

Now, we can initialize a pointer current, which represents the last node of the merged linked list. We then iterate through the two input linked lists, comparing the values of l1 and l2 at each step. We append the smaller of the two nodes to the tail of the merged linked list, and advance the pointer of the node we appended.

When either l1 or l2 is None, we can append the remaining nodes of the other linked list to the merged linked list, and return head

```python

def merge_lists(l1, l2):
    if not l1: return l2
    if not l2: return l1
    if l1.val < l2.val:
        head = l1
        l1 = l1.next
    else:
        head = l2
        l2 = l2.next
    current = head
    while l1 and l2:
        if l1.val < l2.val:
            current.next = l1
            l1 = l1.next
        else:
            current.next = l2
            l2 = l2.next
        current = current.next
    current.next = l1 or l2
    return head
```

Using Dummy node: Notice that in the solution for merging two lists above, the logic for choosing the head of the merged linked list is the same as the logic for choosing the next node to append. We need to handle it as a special case because without it, we wouldn't have a starting point for the merged linked list.
We can avoid this by creating a dummy node to represent the starting point of the merged linked list. This allows us to move directly into the iteration processes without having to introduce a special case to initialize the head of the merged linked list. When the iteration finishes we return dummy.next as the head of the merged linked list.

```python
def merge_two_lists(l1, l2):
    dummy = ListNode()
    tail = dummy
    while l1 and l2:
        if l1.val < l2.val:
            tail.next = l1
            l1 = l1.next
        else:
            tail.next = l2
            l2 = l2.next
        tail = tail.next
    tail.next = l1 or l2
    return dummy.next
```


## 2. Complexity model

Throughout this document, $n$ is the number of nodes in the list.

### General rules

1. Reading or changing the head is $O(1)$.
2. Accessing the node at an index is $O(n)$.
3. Insertion after a known node is $O(1)$.
4. Searching for the insertion point can make the complete operation $O(n)$.
5. A traversal uses $O(1)$ extra space when implemented iteratively.

### Complexity summary

| Operation | Time complexity | Extra space | Reason |
| --- | ---: | ---: | --- |
| Access head | $O(1)$ | $O(1)$ | The head reference is stored directly. |
| Access by index | $O(n)$ | $O(1)$ | Nodes must be followed in order. |
| Search by value | $O(n)$ | $O(1)$ | Every node may need inspection. |
| Insert at head | $O(1)$ | $O(1)$ | Only references change. |
| Insert after known node | $O(1)$ | $O(1)$ | Only neighboring references change. |
| Append with tail reference | $O(1)$ | $O(1)$ | The tail is directly available. |
| Append without tail reference | $O(n)$ | $O(1)$ | The list must be traversed. |
| Remove head | $O(1)$ | $O(1)$ | The head moves to the next node. |
| Remove after known node | $O(1)$ | $O(1)$ | One reference bypasses the removed node. |
| Reverse iteratively | $O(n)$ | $O(1)$ | Every link is redirected once. |

## 3. Where this fits in my mental model

### When I reach for linked lists

I reach for a linked list when the problem is defined in terms of nodes and references, or when it requires:

- Reversing a chain of nodes in place.
- Detecting a cycle.
- Finding the middle node.
- Merging sorted linked lists.
- Removing the $k$-th node from the end.
- Reordering or partitioning nodes without copying their values.

In practice, I usually prefer arrays unless the model itself is explicitly a linked list or direct node references make the updates worthwhile.

### Common problem patterns

| Problem type | Recommended technique | Typical complexity |
| --- | --- | ---: |
| Reverse a list | Three pointers | $O(n)$ |
| Detect a cycle | Fast and slow pointers | $O(n)$ |
| Find the middle | Fast and slow pointers | $O(n)$ |
| Remove node from end | Two pointers with a gap | $O(n)$ |
| Merge sorted lists | Dummy node and two pointers | $O(n + m)$ |
| Find intersection | Pointer switching | $O(n + m)$ |

## 4. Operations cheatsheet

| Operation | Python | TypeScript | Time |
| --- | --- | --- | ---: |
| Create node | `ListNode(value)` | `new ListNode(value)` | $O(1)$ |
| Read value | `node.value` | `node.value` | $O(1)$ |
| Read next | `node.next` | `node.next` | $O(1)$ |
| Insert at head | `head = ListNode(value, head)` | `head = new ListNode(value, head)` | $O(1)$ |

| Find middle | Slow and fast pointers | Slow and fast pointers | $O(n)$ |
| Reverse | Previous/current/next pointers | Previous/current/next pointers | $O(n)$ |

## 5. Important considerations

### Keep the next node before changing a link

During reversal, save `current.next` before assigning a new value to it. Otherwise, the unprocessed part of the list becomes unreachable.

### Distinguish node access from node mutation

Insertion is $O(1)$ only when the relevant node is already known. Finding the node at index $i$ first costs $O(i)$.

### Why I use a dummy node for edge cases

A dummy node before the head simplifies operations that may remove or replace the first real node. It avoids separate logic for an empty list or head removal.

### Prevent lost references and accidental cycles

Changing links in the wrong order can disconnect nodes or create cycles. Draw the affected references before implementing a complex update.

### Recursion uses stack space

Recursive traversal and reversal use $O(n)$ call-stack space and may exceed recursion limits. I prefer an iterative version when the input can be large.
