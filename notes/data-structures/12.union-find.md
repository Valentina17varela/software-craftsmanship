# Union-Find and Disjoint Set Union

## 1. Description and declaration

Union-Find, also called Disjoint Set Union (DSU), maintains a partition of elements into non-overlapping groups. It efficiently answers whether two elements belong to the same component and merges components.

Each component is represented by a root. Two optimizations make operations nearly constant time:

- Path compression makes visited nodes point closer to the root during `find`.
- Union by size or rank attaches the smaller tree below the larger one.

### Python

```python
class UnionFind:
    def __init__(self, size):
        self.parent = list(range(size))
        self.component_size = [1] * size
        self.components = size

    def find(self, node):
        if self.parent[node] != node:
            self.parent[node] = self.find(self.parent[node])
        return self.parent[node]

    def union(self, first, second):
        root_a = self.find(first)
        root_b = self.find(second)
        if root_a == root_b:
            return False
        if self.component_size[root_a] < self.component_size[root_b]:
            root_a, root_b = root_b, root_a
        self.parent[root_b] = root_a
        self.component_size[root_a] += self.component_size[root_b]
        self.components -= 1
        return True

    def connected(self, first, second):
        return self.find(first) == self.find(second)

union_find = UnionFind(5)
union_find.union(0, 1)
union_find.union(1, 2)

print(union_find.connected(0, 2))  # True
print(union_find.connected(0, 4))  # False
print(union_find.components)       # 3
```

### TypeScript

```typescript
class UnionFind {
    private parent: number[];
    private componentSize: number[];
    components: number;

    constructor(size: number) {
        this.parent = Array.from({ length: size }, (_, index) => index);
        this.componentSize = Array(size).fill(1);
        this.components = size;
    }

    find(node: number): number {
        if (this.parent[node] !== node) this.parent[node] = this.find(this.parent[node]);
        return this.parent[node];
    }

    union(first: number, second: number): boolean {
        let rootA = this.find(first);
        let rootB = this.find(second);
        if (rootA === rootB) return false;

        if (this.componentSize[rootA] < this.componentSize[rootB]) [rootA, rootB] = [rootB, rootA];
        this.parent[rootB] = rootA;
        this.componentSize[rootA] += this.componentSize[rootB];
        this.components -= 1;
        return true;
    }

    connected(first: number, second: number): boolean {
        return this.find(first) === this.find(second);
    }
}

const unionFind = new UnionFind(5);
unionFind.union(0, 1);
unionFind.union(1, 2);

console.log(unionFind.connected(0, 2)); // true
console.log(unionFind.connected(0, 4)); // false
console.log(unionFind.components);      // 3
```

## 2. Complexity model

Let $n$ be the number of elements. With path compression and union by size or rank, a sequence of operations has amortized complexity $O(\alpha(n))$ per operation, where $\alpha$ is the inverse Ackermann function. It grows so slowly that it is effectively constant for practical input sizes.

| Operation | Amortized time | Extra space |
| --- | ---: | ---: |
| Create $n$ singleton sets | $O(n)$ | $O(n)$ |
| Find representative | $O(\alpha(n))$ | $O(1)$ iterative or recursion depth |
| Union two sets | $O(\alpha(n))$ | $O(1)$ |
| Connectivity query | $O(\alpha(n))$ | $O(1)$ |
| Component count | $O(1)$ | $O(1)$ |
| Component size | $O(\alpha(n))$ | $O(1)$ |

Without balancing, trees can become chains and operations can degrade to $O(n)$. Using only one optimization is better than neither, but both provide the standard bound.

## 3. Competitive programming use cases

### When to use Union-Find

Use DSU for connectivity in an undirected graph when edges are added or processed as a batch and path traversal is unnecessary.

| Problem type | DSU strategy | Typical complexity |
| --- | --- | ---: |
| Count connected components | Decrement count after successful union | $O((V + E)\alpha(V))$ |
| Detect undirected cycle | Cycle if endpoints already share a root | $O(E\alpha(V))$ |
| Kruskal minimum spanning tree | Union endpoints in increasing edge-weight order | $O(E\log E)$ overall |
| Redundant connection | First edge whose union fails | $O(E\alpha(V))$ |
| Dynamic connectivity by additions | Union each newly connected pair | Near $O(1)$ per operation |
| Account or identity merging | Union records sharing an identifier | Input-dependent |

### Example: detect a redundant edge

If both endpoints already have the same representative, adding their edge creates a cycle.

```python
# Python
edges = [(0, 1), (1, 2), (2, 3), (0, 3)]
parent = list(range(4))
size = [1] * 4

def find(node):
    while node != parent[node]:
        parent[node] = parent[parent[node]]
        node = parent[node]
    return node

def union(first, second):
    root_a, root_b = find(first), find(second)
    if root_a == root_b:
        return False
    if size[root_a] < size[root_b]:
        root_a, root_b = root_b, root_a
    parent[root_b] = root_a
    size[root_a] += size[root_b]
    return True

redundant = next(edge for edge in edges if not union(*edge))
print(redundant)  # (0, 3)
```

```typescript
// TypeScript
const edges: Array<[number, number]> = [[0, 1], [1, 2], [2, 3], [0, 3]];
const parent = Array.from({ length: 4 }, (_, index) => index);
const size = Array(4).fill(1);

function find(node: number): number {
    while (node !== parent[node]) {
        parent[node] = parent[parent[node]];
        node = parent[node];
    }
    return node;
}

function union(first: number, second: number): boolean {
    let rootA = find(first);
    let rootB = find(second);
    if (rootA === rootB) return false;
    if (size[rootA] < size[rootB]) [rootA, rootB] = [rootB, rootA];
    parent[rootB] = rootA;
    size[rootA] += size[rootB];
    return true;
}

const redundant = edges.find(([first, second]) => !union(first, second));
console.log(redundant); // [0, 3]
```

## 4. Operations cheatsheet

| Operation | Core logic | Complexity |
| --- | --- | ---: |
| Initialize | `parent[i] = i`, size or rank is initial value | $O(n)$ |
| Find | Follow parent pointers to root | $O(\alpha(n))$ amortized |
| Compress path | Point visited nodes toward root | Included in `find` |
| Union by size | Attach smaller root below larger root | $O(\alpha(n))$ amortized |
| Connected | Compare `find(a)` and `find(b)` | $O(\alpha(n))$ amortized |
| Component count | Decrement only after successful union | $O(1)$ read |
| Component size | Read size at `find(node)` | $O(\alpha(n))$ amortized |
| Cycle check | A union fails when roots match | $O(\alpha(n))$ amortized |

## 5. Important considerations

### Update metadata only on roots

Component size and rank belong to representatives. Read or modify them only after calling `find`.

### A failed union carries useful information

When two endpoints already share a root, the edge is redundant and would create a cycle in an undirected graph.

### DSU does not recover paths

Union-Find answers connectivity, not how vertices are connected. Use BFS or DFS when the actual path, traversal order, or distances are required.

### Standard DSU does not handle deletions naturally

It supports additions and merges efficiently. Removing an edge may split a component and usually requires an offline technique, rollback DSU, or another dynamic-connectivity structure.

### Match indexes to input labels

Convert one-based labels to zero-based indexes consistently, or allocate arrays with an unused index zero. Many DSU bugs are indexing errors rather than algorithm errors.

### Recursive `find` depends on balancing

Union by size keeps trees shallow. An iterative `find`, as used in the cycle example, avoids recursion limits entirely.
