# Deques

## 1. Description and declaration

A deque, or double-ended queue, supports insertion and removal at both the front and the back in $O(1)$ time. It can behave as both a queue and a stack.

Python provides `collections.deque`. TypeScript has no built-in deque; using `Array.shift()` repeatedly is $O(n)$, so an indexed implementation is preferable.

### Python

```python
from collections import deque

values = deque([2, 3])
values.appendleft(1)
values.append(4)

print(values.popleft())  # 1
print(values.pop())      # 4
```

### TypeScript

```typescript
class Deque<T> {
    private values = new Map<number, T>();
    private frontIndex = 0;
    private backIndex = 0;

    get size(): number {
        return this.backIndex - this.frontIndex;
    }

    pushFront(value: T): void {
        this.frontIndex -= 1;
        this.values.set(this.frontIndex, value);
    }

    pushBack(value: T): void {
        this.values.set(this.backIndex, value);
        this.backIndex += 1;
    }

    popFront(): T | undefined {
        if (this.size === 0) return undefined;
        const value = this.values.get(this.frontIndex);
        this.values.delete(this.frontIndex);
        this.frontIndex += 1;
        return value;
    }

    popBack(): T | undefined {
        if (this.size === 0) return undefined;
        this.backIndex -= 1;
        const value = this.values.get(this.backIndex);
        this.values.delete(this.backIndex);
        return value;
    }

    peekFront(): T | undefined {
        return this.values.get(this.frontIndex);
    }

    peekBack(): T | undefined {
        return this.values.get(this.backIndex - 1);
    }
}

const values = new Deque<number>();
values.pushBack(2);
values.pushFront(1);
values.pushBack(3);

console.log(values.popFront()); // 1
console.log(values.popBack());  // 3
```

## 2. Complexity model

Let $n$ be the number of elements in the deque.

| Operation | Time | Extra space |
| --- | ---: | ---: |
| Peek front or back | $O(1)$ | $O(1)$ |
| Add front or back | $O(1)$ amortized | $O(1)$ amortized |
| Remove front or back | $O(1)$ | $O(1)$ |
| Length | $O(1)$ | $O(1)$ |
| Access arbitrary index | $O(n)$ conceptually | $O(1)$ |
| Search | $O(n)$ | $O(1)$ |
| Iterate | $O(n)$ | $O(1)$ excluding output |

A deque is optimized for its endpoints, not random access. Python's deque supports indexing, but access near the middle is $O(n)$.

## 3. Where this fits in my mental model

### When I reach for a deque

- BFS and level-order traversal.
- Sliding-window maximum or minimum.
- Monotonic queues.
- 0-1 BFS, adding weight-zero edges to the front and weight-one edges to the back.
- Palindrome checks from both ends.
- Simulations that modify both endpoints.

| Problem type | Deque role | Typical complexity |
| --- | --- | ---: |
| Standard BFS | FIFO queue | $O(V + E)$ |
| Sliding-window maximum | Decreasing deque of candidate indexes | $O(n)$ |
| 0-1 BFS | Prioritize zero-weight edges | $O(V + E)$ |
| Palindrome | Compare both endpoints | $O(n)$ |
| Task simulation | Add and remove at either end | Usually $O(n)$ |

### Example: sliding-window maximum

The deque stores indexes whose values are in decreasing order. Smaller values at the back cannot become a future maximum after a larger, newer value arrives.

```python
# Python
from collections import deque

numbers = [1, 3, -1, -3, 5, 3, 6, 7]
window_size = 3
candidates = deque()
maximums = []

for right, number in enumerate(numbers):
    while candidates and candidates[0] <= right - window_size:
        candidates.popleft()
    while candidates and numbers[candidates[-1]] <= number:
        candidates.pop()
    candidates.append(right)
    if right >= window_size - 1:
        maximums.append(numbers[candidates[0]])

print(maximums)  # [3, 3, 5, 5, 6, 7]
```

```typescript
// TypeScript
const numbers = [1, 3, -1, -3, 5, 3, 6, 7];
const windowSize = 3;
const candidates = new Map<number, number>();
const maximums: number[] = [];
let front = 0;
let back = 0;

for (let right = 0; right < numbers.length; right += 1) {
    while (front < back && candidates.get(front)! <= right - windowSize) {
        candidates.delete(front);
        front += 1;
    }
    while (front < back && numbers[candidates.get(back - 1)!] <= numbers[right]) {
        back -= 1;
        candidates.delete(back);
    }
    candidates.set(back, right);
    back += 1;
    if (right >= windowSize - 1) maximums.push(numbers[candidates.get(front)!]);
}

console.log(maximums); // [3, 3, 5, 5, 6, 7]
```

Each index enters and leaves the deque at most once, so the total time is $O(n)$ and the extra space is $O(k)$ for window size $k$.

## 4. Operations cheatsheet

| Operation | Python `deque` | TypeScript custom deque | Time |
| --- | --- | --- | ---: |
| Create | `deque(values)` | `new Deque<T>()` | $O(n)$ / $O(1)$ |
| Length | `len(values)` | `values.size` | $O(1)$ |
| Add front | `appendleft(value)` | `pushFront(value)` | $O(1)$ |
| Add back | `append(value)` | `pushBack(value)` | $O(1)$ |
| Remove front | `popleft()` | `popFront()` | $O(1)$ |
| Remove back | `pop()` | `popBack()` | $O(1)$ |
| Peek front | `values[0]` | `peekFront()` | $O(1)$ |
| Peek back | `values[-1]` | `peekBack()` | $O(1)$ |
| Rotate | `rotate(steps)` | Implement endpoint moves | $O(k)$ |
| Clear | `clear()` | Reset storage and indexes | $O(n)$ or implementation-dependent |

## 5. Important considerations

### Why I avoid repeated `shift()` in TypeScript

Removing the first array element reindexes the remaining elements and costs $O(n)$. I use a head index, ring buffer, linked structure, or tested deque implementation instead.

### A monotonic deque stores candidates, not every value

Remove expired indexes from the front and dominated values from the back. Store indexes when expiration depends on position.

### Distinguish deque from priority queue

A deque removes from physical endpoints. A priority queue removes according to priority, regardless of insertion position.

### Handle empty removals

Python raises `IndexError` when popping an empty deque. The TypeScript example returns `undefined`; account for that in strict code.

### Compact long-lived head-index queues

A simple TypeScript array plus head index can retain consumed slots. For a long-lived process, I periodically compact the array or use a ring buffer; the retained space matters much more there than in a short-lived script.
